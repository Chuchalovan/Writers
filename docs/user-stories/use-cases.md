## Auth и аккаунт

### UC-AUTH-01 — Регистрация

| Поле | Значение |
|------|----------|
| **Актор** | Гость |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | FR-AUTH-01 · [US-AUTH-001](./stories/US-AUTH-001.md) |

**Предусловия:** открыт экран регистрации; email ещё не занят.

**Триггер:** гость нажимает «Зарегистрироваться» / «Создать аккаунт».

**Основной поток:**

1. Указывает email и пароль.
2. Система проверяет формат email и политику пароля.
3. Создаётся аккаунт; устанавливается сессия.
4. Пользователь попадает в приложение (список проектов / empty-state).

**Альтернативы:**

- A1. Уже есть аккаунт — переход ко входу (UC-AUTH-02).

**Исключения:**

- E1. Невалидный email / слабый пароль — ошибка у поля, аккаунт не создаётся.
- E2. Email уже занят — понятное сообщение, аккаунт не дублируется.
- E3. Ошибка сети/сервера — сообщение и повтор; частичный аккаунт не оставляется «висящим» для пользователя.

**Результат:** автор авторизован и может создавать проекты.

### UC-AUTH-02 — Вход и выход

| Поле | Значение |
|------|----------|
| **Актор** | Гость (вход) / Автор (выход) |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | FR-AUTH-02 |

**Предусловия (вход):** аккаунт существует.

**Триггер:** гость отправляет форму входа **или** автор выбирает «Выйти».

**Основной поток (вход):**

1. Вводит email и пароль.
2. Система проверяет учётные данные.
3. Устанавливается сессия; открывается приложение.
4. Защищённые маршруты доступны.

**Основной поток (выход):**

1. Автор подтверждает выход (если UI требует) или выходит сразу.
2. Сессия завершается; защищённые маршруты недоступны.

**Исключения:**

- E1. Неверный пароль / неизвестный email — общая безопасная ошибка (без утечки, существует ли аккаунт, если так принято политикой безопасности).
- E2. Истечение сессии — редирект на вход; несохранённый текст редактора обрабатывается UC-ED-03.
- E3. Защищённый URL без сессии — редирект на вход.

**Результат:** сессия установлена или завершена предсказуемо.

### UC-AUTH-03 — Подтверждение email

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / MVP Beta |
| **Связи** | FR-AUTH-03 |

**Предусловия:** аккаунт создан; email ещё не подтверждён.

**Триггер:** автор открывает одноразовую ссылку из письма **или** запрашивает повторную отправку.

**Основной поток:**

1. Переходит по ссылке.
2. Система помечает email подтверждённым; ссылка больше не действует.
3. Автор видит подтверждение и продолжает работу.

**Альтернативы:**

- A1. Повторная отправка письма — предыдущая ссылка инвалидируется (одна активная). Политика: [ТЗ §8.1](../tz/TZ.md#81-аутентификация-и-аккаунт).

**Исключения:**

- E1. Ссылка истекла / уже использована — сообщение и кнопка «Отправить ещё раз».
- E2. Без подтверждения AI, удаление аккаунта, выгрузка всего аккаунта и смена email запрещены; письмо и экспорт проекта доступны, в шапке — баннер. Политика: [ТЗ §8.1](../tz/TZ.md#81-аутентификация-и-аккаунт).

**Результат:** email подтверждён; политика ограничений снята.

### UC-AUTH-04 — Восстановление пароля

| Поле | Значение |
|------|----------|
| **Актор** | Гость (владелец email) |
| **Приоритет** | P0 / MVP Beta |
| **Связи** | FR-AUTH-04 |

**Предусловия:** аккаунт с этим email существует (для отправителя письма).

**Триггер:** на экране входа выбирает «Забыли пароль?».

**Основной поток:**

1. Указывает email.
2. Система отправляет письмо со ссылкой (если аккаунт есть).
3. Открывает ссылку, задаёт новый пароль.
4. Новый пароль принимается; вход со старым невозможен.
5. Старые сессии инвалидируются по политике.

**Исключения:**

- E1. Email не найден — тот же UX, что и «письмо отправлено» (без enumeration), либо явное сообщение — единообразно с политикой безопасности.
- E2. Ссылка истекла — запрос нового письма.
- E3. Новый пароль не проходит политику — ошибка у поля, пароль не меняется.

**Результат:** автор входит с новым паролем.

### UC-AUTH-06 — Удаление аккаунта

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / MVP Beta |
| **Связи** | FR-AUTH-06 |

**Предусловия:** есть сессия.

**Триггер:** в настройках выбирает удаление аккаунта.

**Основной поток:**

1. Система требует **явное** подтверждение (не один случайный клик).
2. Автор при необходимости выгружает данные (экспорт аккаунта).
3. Подтверждает удаление.
4. Аккаунт недоступен для входа; данные обрабатываются по политике хранения.

**Альтернативы:**

- A1. Отмена на шаге подтверждения — ничего не удаляется.

**Исключения:**

- E1. Выгрузка не удалась — удаление **не** выполняется, пока автор не повторит выгрузку или явно не подтвердит «Удалить без выгрузки». Политика: [ТЗ §8.1](../tz/TZ.md#81-аутентификация-и-аккаунт).
- E2. Ошибка удаления — аккаунт остаётся рабочим; понятная ошибка.

**Результат:** аккаунт нельзя использовать для входа.

## Проекты

### UC-PRJ-01 — Создание проекта

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | PRD S1 · BRD UC-1 · FR-PRJ-01, FR-PRJ-05 · [US-PROJECT-001](./stories/US-PROJECT-001.md) |

**Предусловия:** автор авторизован.

**Триггер:** нажимает «Новый проект».

**Основной поток:**

1. Указывает **только название** (обязательно).
2. При необходимости выбирает путь: «Начать писать» / «Спланировать сюжет» / «Добавить материалы».
3. Система создаёт проект.
4. Открывается экран по пути: первая сцена / структура / материалы; иначе — обзор проекта.

**Альтернативы:**

- A1. Путь не выбран — проект создаётся, открывается обзор с подсказками следующего шага.
- A2. «Начать писать» — создаётся (или предлагается) первая сцена, открывается редактор.
- A3. «Спланировать сюжет» — открывается навигатор / сюжет (на Alpha метод не обязателен; метод — UC-KN-06 на Beta).
- A4. «Добавить материалы» — открывается база знаний.

**Исключения:**

- E1. Пустое название — валидация, проект не создаётся.
- E2. Отмена формы — пустой проект не создаётся.
- E3. Ошибка сети — сообщение и повтор.

**Результат:** проект сохранён; есть понятный следующий шаг. Метод сюжета **не** навязан.

2. Открывает проект кликом.

**Альтернативы:**

- A1. Поиск / фильтр по названию.

- E3. Ошибка дублирования — исходник цел.

### UC-PRJ-03 — Возврат к проекту

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | PRD S5 · BRD UC-4 · FR-PRJ-06 |

**Предусловия:** проект существует.

**Триггер:** открывает проект с dashboard / обзора.

**Основной поток:**

1. Видит последнюю сцену (или точку продолжения).
2. Видит прогресс **без ложного %**, если нет цели по объёму.
3. Видит 1–3 следующих действия.
4. Одним действием продолжает письмо («Продолжить»).

**Альтернативы:**

- A1. Пустой проект — onboarding-подсказки (написать / спланировать / материалы), не фиктивная готовность.

**Исключения:**

- E1. Последняя сцена удалена — точка продолжения смещается на соседний узел или обзор, без 404-ловушки.
- E2. Ошибка загрузки обзора — error-state с повтором.

**Результат:** автор возобновляет работу без поиска «где я был».

## Структура рукописи

### UC-MS-01 — Планирование структуры

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | PRD S2 · FR-MS-01…04, FR-MS-06 |

**Предусловия:** проект открыт.

**Триггер:** в навигаторе создаёт или меняет части, главы, сцены.

**Основной поток:**

1. Создаёт узел (часть / глава / сцена).
2. Переименовывает при необходимости.
3. Меняет порядок (включая drag-and-drop).
4. Задаёт статус сцены: idea → planned → draft → revision → ready (статус **не** блокирует редактирование).
5. Дерево сохраняется; порядок воспроизводится после перезагрузки.

**Альтернативы:**

- A1. Сцена без главы — в «Нераспределённые» (FR-MS-04).
- A2. Перенос главы вместе со сценами — иерархия не рвётся.
- A3. Поиск по подстроке названия в навигаторе — дерево фильтруется.
- A4. Сворачивание уровней, контекстное меню.

**Исключения:**

- E1. Ошибка сохранения порядка — UI откатывается, уведомление, данные на сервере не «полупереставлены» скрыто.
- E2. Пустое имя узла — валидация или автоимя по правилам UI, узел-призрак не создаётся.

**Результат:** структура проекта согласована и устойчива к reload.

### UC-MS-02 — Удаление и восстановление узлов

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | FR-MS-05 |

**Предусловия:** в дереве есть узел.

**Триггер:** автор удаляет часть / главу / сцену.

**Основной поток:**

1. Система запрашивает подтверждение.
2. Узел уходит в soft delete / корзину (не уничтожается сразу).
3. Автор восстанавливает узел из корзины — место в дереве восстанавливается по правилам продукта (исходный родитель или «Нераспределённые»).

**Исключения:**

- E1. Отмена подтверждения — ничего не удаляется.
- E2. Удаление главы не должно скрыто каскадом уничтожать сцены без возможности восстановления.
- E3. Открытая в редакторе удалённая сцена — понятный empty/deleted-state, не молчаливая потеря текста (текст в soft delete).

**Результат:** удаление обратимо в рамках политики корзины.

## Редактор

### UC-ED-01 — Написание сцены

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | PRD S3 · BRD UC-3 · FR-ED-01, FR-ED-03, FR-ED-05, FR-ED-07 · [US-EDITOR-001](./stories/US-EDITOR-001.md) |

**Предусловия:** сцена существует (или только что создана путём «Начать писать»).

**Триггер:** открывает сцену из навигатора или «Продолжить».

**Основной поток:**

1. Пишет в редакторе (TipTap): абзацы, bold/italic/strike, списки, undo/redo.
2. Видит статус сохранения; ввод **не** ждёт сеть.
3. Видит счётчик слов/знаков без перезагрузки страницы.
4. При необходимости включает режим фокуса (Ctrl/Cmd+Shift+F); Escape закрывает оверлеи.
5. При возврате восстанавливаются позиция курсора и прокрутки.

**Альтернативы:**

- A1. Ctrl/Cmd+S — немедленная синхронизация.
- A2. Alt/Option+↑/↓ — соседняя сцена.
- A3. Скрытие боковых панелей, фокус на тексте.

**Исключения:**

- E1. Потеря сети — UC-ED-03; введённый текст не теряется.
- E2. AI не получает весь проект без выбора контекста (правило продукта; AI — UC-AI-01).

**Результат:** текст автосохранён; автор не отвлекается на ручное сохранение.

### UC-ED-02 — Контекст сцены

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | FR-ED-02, FR-ED-06 |

**Предусловия:** сцена открыта.

**Триггер:** открывает контекстную панель или поля метаданных сцены.

**Основной поток:**

1. Заполняет метаданные: цель, конфликт, POV, локация, участники (поля опциональны).
2. Переключает вкладки панели: Сцена / Персонажи / Мир.
3. Видит связанных героев и локацию, не покидая редактор.
4. Метаданные сохраняются.

**Альтернативы:**

- A1. Создание героя / локации из контекста сцены → UC-KN-01 / UC-KN-02.
- A2. Трёхколоночный layout: навигатор \| текст \| контекст; панели скрываются.

**Исключения:**

- E1. Связанная сущность удалена — broken-ссылка с понятным UI, не падение редактора.
- E2. Ошибка сохранения метаданных — уведомление; текст сцены не откатывается.

**Результат:** факты сцены доступны рядом с текстом.

### UC-ED-03 — Письмо без сети

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | FR-ED-04 · NFR-05 |

**Предусловия:** сцена открыта; автор уже вводил или вводит текст.

**Триггер:** пропадает сеть **или** закрывается/убивается вкладка с несинхронизированным вводом.

**Основной поток:**

1. Редактор продолжает принимать ввод (локальный отклик ≤ 50 мс — NFR-02).
2. Статус показывает, что сохранение локальное / ожидает сеть.
3. После восстановления сети — синхронизация на сервер.
4. Подтверждённый (успешно синхронизированный) текст не теряется.

**Альтернативы:**

- A1. Kill tab / reload — локальное восстановление несинка при следующем открытии сцены.

**Исключения:**

- E1. Конфликт версий после офлайна — **не** молчаливое затирание; явный merge — UC-ED-04 (gate Beta). На Alpha минимум: не потерять более новую локальную копию и показать, что есть расхождение.
- E2. Переполнение локального буфера — предупреждение; уже введённое не выбрасывать без сообщения.

**Результат:** нет потери введённого текста в типовом offline-сценарии.

## База знаний

### UC-KN-01 — Описание героя

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | PRD S4 · BRD UC-3a · FR-KN-01, FR-KN-02 |

**Предусловия:** проект открыт.

**Триггер:** создаёт или открывает карточку героя из «Персонажи» или из контекста сцены.

**Основной поток:**

1. Указывает **имя** (обязательно).
2. Опционально заполняет: роль, краткое описание, внешность, цели/мотивация, заметки.
3. Сохраняет. Опциональные поля не блокируют сохранение.
4. При необходимости привязывает героя к сценам (участник сцены).
5. Карточка доступна в списке и в контекстной панели сцены.

**Альтернативы:**

- A1. Редактирование существующей карточки.
- A2. Снять героя со сцены — герой остаётся в базе.

**Исключения:**

- E1. Без имени — не сохраняется.
- E2. Удаление героя — подтверждение; связи со сценами не каскадятся скрытно (снимаются или помечаются broken).
- E3. Связи между героями при удалении — UC-KN-03.

**Результат:** описание героя — единый факт проекта, не только текст в сцене.

### UC-KN-03 — Связи между героями

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P0 / Closed Alpha |
| **Связи** | PRD S4b · BRD UC-3b · FR-KN-10 |

**Предусловия:** в проекте есть как минимум два героя.

**Триггер:** на карточке героя добавляет связь с другим героем.

**Основной поток:**

1. Выбирает второго героя.
2. Указывает тип/роль связи (семья, союзник, враг, иное) и опциональный комментарий.
3. Сохраняет.
4. Связь видна на карточках обоих участников **или** как минимум у инициатора с переходом к другому.
5. Можно изменить тип/комментарий или удалить связь (герои остаются).

**Альтернативы:**

- A1. Список связей героя без визуального графа (граф — P2, не этот UC).

**Исключения:**

- E1. Нельзя связать героя с самим собой.
- E2. Дубликат той же пары + типа — валидация или обновление существующей связи.
- E3. Удаление героя — связи снимаются или помечаются broken с понятным UI.

**Результат:** отношения персонажей удерживаются в проекте без внешней таблицы.

### UC-KN-06 — Сюжет по методу

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P1 / MVP Beta |
| **Связи** | BRD UC-2 · FR-KN-05 · [plot-methods.md](../brd/plot-methods.md) |

**Предусловия:** проект существует. На Alpha допустим только `blank`.

**Триггер:** при создании проекта или в разделе «Сюжет» выбирает метод **или** пустую структуру.

**Основной поток:**

1. Выбирает **один** метод: `three-act` / `heros-journey` / `beat-sheet` / `blank` (Must к Beta).
2. Система создаёт каркас (акты/биты/точки) с пояснениями **простым языком**.

**Альтернативы:**

- A1. Старт без метода (`blank`) — свободное письмо, каркас можно добавить позже.
- A2. Смена или ослабление метода — текст рукописи не удаляется.
- A3. Сюжетные линии (Storyline) — отдельные нити на доске.

**Исключения:**

- E1. Метод не выбран — не блокирует письмо.
- E2. Удаление карточки плана не удаляет связанную сцену без подтверждения.

**Результат:** есть каркас сюжета или явный отказ от метода; рукопись цела.

## AI

### UC-AI-01 — AI-помощь по контексту

| Поле | Значение |
|------|----------|
| **Актор** | Автор |
| **Приоритет** | P1 / MVP Beta |
| **Связи** | PRD S7 · BRD UC-6 · FR-AI-01…04 |

**Предусловия:** автор в сцене или выделил текст / сущности; согласие и настройки приватности доступны **до** первого запроса (FR-AI-04).

**Триггер:** запускает AI для сцены / выделения / выбранных сущностей.

**Основной поток:**

1. Видит состав контекста **до** отправки (Level 0–3; список сущностей).
2. При необходимости меняет состав контекста.
3. Отправляет запрос.
4. Получает предложение; видит источники внутри проекта.
5. **Принимает** / **принимает фрагмент** / **отклоняет** (diff). Текст рукописи меняется только после явного принятия.

**Альтернативы:**

- A1. Анализ / редактура выделенного фрагмента — то же правило accept/diff.
- A2. Отказ от AI — обычное письмо без деградации редактора.

**Исключения:**

- E1. Отказ провайдера / таймаут — понятная ошибка, текст не меняется.
- E2. Контекст Level 4–5 (весь проект) — вне MVP (P2), недоступен или явно заблокирован.
- E3. Нет согласия на политику — запрос не уходит.
