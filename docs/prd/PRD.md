## 1. Краткое резюме

Авторы художественной прозы держат текст, структуру, персонажей и заметки в разных инструментах — связи теряются, план расходится с рукописью, универсальный AI не знает контекст проекта.

«Манускрипт» объединяет проект книги, структуру частей/глав/сцен, базу знаний (персонажи, мир, сюжет) и редактор с контекстной помощью AI в одном спокойном desktop-first пространстве.

Ожидаемый результат MVP (MVP Beta = P0 + P1): автор создаёт структуру и последовательно пишет первый черновик без потери текста, с экспортом и без навязанной генерации «книги одной кнопкой».

## 2. Контекст и формулировка проблемы

### 2.1. Текущая ситуация

| Утверждение | Тип | Комментарий |
|-------------|-----|-------------|
| Материалы книги разнесены по редактору, таблицам, заметкам и чатам | **Гипотеза** (продуктовая) | Подтверждается интервью / Alpha; зафиксирована в v1.0 |
| Универсальные AI-чаты не знают контекст проекта | **Гипотеза** | Проверяется сценарием AI с выбором контекста (P1) |
| Сложные писательские комбайны перегружают новичка | **Гипотеза** | UX-принцип прогрессивного раскрытия |
| Продукт уже в разработке: Phase 0 и Sprint 1–2 частично завершены | **Факт** | См. Roadmap |

### 2.2. Проблема одним абзацем

**Когда** автор пишет художественную прозу, **он сталкивается с** разрозненными инструментами для текста, структуры и фактов мира, **из-за чего** теряются связи, растёт когнитивная нагрузка и проект чаще бросается до черновика.

### 2.3. Ключевые боли

1. Трудно перейти от идеи к последовательному плану.  
2. Сложно удерживать арки, хронологию и причинно-следственные связи.  
3. План и рукопись быстро расходятся.  
4. Поиск факта прерывает поток письма.  
5. AI без контекста проекта навязывает чужой голос.  
6. Профессиональные системы требуют долгого освоения.

### 2.4. Последствия бездействия

Автор остаётся в связке «Word/Docs + Notion/таблицы + ChatGPT» → выше риск противоречий и отказа от проекта; продукт не проверяет гипотезу единой среды.

### 2.5. Продуктовая гипотеза

**Гипотеза:** если сюжет, персонажи, мир и рукопись связаны в одной системе, а AI предлагает варианты только по выбранному контексту и не меняет текст без явного действия, то автор быстрее доходит до законченного черновика и реже бросает проект.

## 3. Цели, результаты и не-цели

### 3.1. Бизнес-цели

| ID | Цель | Горизонт | Связь |
|----|------|----------|-------|
| BG-1 | Запустить Closed Alpha с ядром «писать + структура + описание героев/локаций + связи между героями + экспорт» | Phase 1 | [BRD](../brd/BRD.md) BG-1 |
| BG-2 | Достичь MVP Beta (P0 + P1) и проверить ценность на ≥5 авторах | Phase 2 | BRD BG-2 |
| BG-3 | Подготовить монетизацию и публичный запуск | Phase 3 | DEC-004 |

### 3.2. Пользовательские результаты

| ID | Результат | Как поймём |
|----|-----------|------------|
| UR-1 | Автор создаёт проект и первую сцену без длинной настройки | Time to first scene; путь onboarding |
| UR-2 | Автор пишет черновик в связанной структуре | ≥300 слов; ≥3 структурных элемента |
| UR-3 | Автор возвращается к проекту и продолжает без «с нуля» | Обзор: continue + next step; D7 |
| UR-4 | Автор забирает рукопись из сервиса | Экспорт DOCX/TXT (Alpha), расширенный (Beta) |

### 3.3. Операционные / процессные цели

- Сократить время поиска факта по проекту (контекстная панель + поиск).  
- Сделать прогресс видимым без токсичной «геймификации».  
- Обеспечить сохранность текста (автосохранение + локальный буфер).

### 3.4. Не-цели текущих версий (Won't / вне MVP)

- Книжная социальная сеть и публичные страницы книг.  
- Маркетплейс редакторов / издательств.  
- Профессиональная вёрстка печатной книги.  
- Автопубликация на площадках.  
- Real-time соавторство и комментарии редактора.  
- Генерация целой книги одной командой.  
- Полнофункциональное mobile-приложение (mobile = ограниченный режим, см. NFR).  
- Пользовательские плагины, голосовой ввод, генерация изображений.

Детали бизнес-метрик с TBD-числами: [BRD §6](../brd/BRD.md).

## 4. Пользователи, роли и условия использования

### 4.1. Сегменты

| Сегмент | Описание | Потребность |
|---------|----------|-------------|
| Начинающий автор | Первая–вторая книга; есть идея и куски текста | Подсказки, шаблоны, понятный следующий шаг |
| Автор-планировщик | Строит сюжет заранее | Структура, связи, таймлайн, фильтры |
| Автор-импровизатор | Начинает со сцены | Старт без мастера; структура по мере роста |

### 4.2. Jobs to be Done

- Когда появилась идея книги — быстро зафиксировать и понять следующий шаг.  
- Когда планирую сюжет — видеть последовательность и пробелы.  
- Когда пишу сцену — видеть релевантный контекст, не покидая редактор.  
- Когда сомневаюсь — получить вопросы/варианты, сохранив контроль.  
- Когда возвращаюсь после перерыва — за минуты вспомнить состояние проекта.  
- Когда рукопись готова — экспортировать без привязки к сервису.

### 4.3. Роли и права (MVP)

| Роль | Права |
|------|-------|
| Владелец аккаунта / автор проекта | Полный CRUD своих проектов и сущностей; экспорт; настройки AI; удаление аккаунта |
| Гость / соавтор | **Вне MVP** (ProjectMember — post-MVP) |

### 4.4. Условия использования

- **Основной контекст:** desktop браузер, длительные сессии письма.  
- **Решение:** desktop-first; на узких экранах — read-only / ограниченное редактирование (**DEC-008**, Proposed).  
- **Языки:** интерфейс ru и en.

### 4.5. Принципы UX (продуктовые ограничения на поведение)

1. **Автор главный** — AI не меняет текст без явного действия; предложения можно принять / принять частично / отклонить.  
2. **Прогрессивное раскрытие** — простой путь новичка; глубина не блокирует старт.  
3. **Контекст рядом с текстом** — персонажи, локация, цель сцены в панели.  
4. **Спокойный интерфейс** — концентрация, минимум шума (визуал — в design handoff).  
5. **Данные принадлежат автору** — автосохранение, версии, экспорт, понятные настройки AI.

## 5. Основные сценарии

Для каждого сценария: триггер → шаги → результат → исключения. Полный каталог use case — [use-cases.md](../user-stories/use-cases.md); детальные AC — в [User Stories](../user-stories/).

### S1. Создание проекта

| | |
|--|--|
| **Триггер** | Авторизованный пользователь нажимает «Новый проект» |
| **Шаги** | 1) Указывает название (обязательно). 2) При необходимости выбирает путь onboarding: «Начать писать» / «Спланировать сюжет» / «Добавить материалы». 3) Система создаёт проект и открывает обзор или первую сцену по пути. |
| **Результат** | Проект сохранён; есть понятный следующий шаг |
| **Исключения** | Пустое название — ошибка валидации, проект не создаётся. Отмена формы — пустой проект не создаётся. Ошибка сети — сообщение и возможность повторить |

**Приоритет:** P0 / Must (Alpha).

### S2. Планирование структуры рукописи

| | |
|--|--|
| **Триггер** | Автор в навигаторе создаёт части, главы, сцены |
| **Шаги** | CRUD узлов; смена порядка (в т.ч. drag-and-drop); статусы сцен; при необходимости — «Нераспределённые» сцены |
| **Результат** | Дерево сохранено; порядок воспроизводится после перезагрузки |
| **Исключения** | Удаление — подтверждение + soft delete / восстановление. Перенос главы со сценами не рвёт иерархию. Ошибка сохранения порядка — откат UI + уведомление |

**Приоритет:** P0 / Must (Alpha); DnD — P0, статус в матрице.

### S3. Написание сцены

| | |
|--|--|
| **Триггер** | Автор открывает сцену из навигатора или «Продолжить» |
| **Шаги** | Пишет в редакторе; видит статус сохранения, счётчик слов; при необходимости открывает контекстную панель и режим фокуса |
| **Результат** | Текст автосохранён; позиция курсора/прокрутки восстанавливается при возврате |
| **Исключения** | Потеря сети — локальный буфер, без потери введённого текста; после восстановления — синхронизация. Конфликт версий — явный UX merge (Beta gate). AI не получает весь проект без выбора контекста |

**Приоритет:** P0 / Must (Alpha); история версий / merge — P0 к Beta.

### S4. Описание героя (персонажа)

| | |
|--|--|
| **Триггер** | Автор создаёт или открывает карточку героя из раздела «Персонажи» или из контекста сцены |
| **Шаги** | Указывает имя (обязательно); заполняет описание героя (роль, краткое описание, внешность, цели/мотивация, заметки — поля опциональны и не блокируют сохранение); привязывает героя к сценам |
| **Результат** | Карточка героя сохранена; описание доступно в разделе и в контекстной панели сцены |
| **Исключения** | Без имени — не сохраняется. Удаление — подтверждение; связи со сценами не каскадятся скрытно |

**Приоритет:** P0 / Must (Alpha) — входит в MVP.

### S4a. Описание локации

| | |
|--|--|
| **Триггер** | Автор создаёт или открывает локацию (статья мира типа «локация») |
| **Шаги** | Указывает название (обязательно); заполняет описание места, тип, теги/заметки (опционально); при необходимости связывает локацию со сценами |
| **Результат** | Локация сохранена и доступна в «Мир» и в метаданных/контексте сцены |
| **Исключения** | Без названия — не сохраняется. Удаление — подтверждение |

**Приоритет:** P0 / Must (Alpha) — входит в MVP.

### S4b. Связи между героями

| | |
|--|--|
| **Триггер** | Автор на карточке героя добавляет связь с другим героем проекта |
| **Шаги** | Выбирает второго героя; указывает тип/роль связи (например, семья, союзник, враг, иное) и опциональный комментарий; сохраняет. Может редактировать или удалить связь |
| **Результат** | Связь видна на карточках обоих участников (или как минимум у инициатора с переходом к другому); список связей героя доступен без отдельного визуального графа |
| **Исключения** | Нельзя связать героя с самим собой. Удаление героя — связи снимаются или помечаются broken с понятным UI. Дубликат той же пары+типа — валидация или обновление |

**Приоритет:** P0 / Must (Alpha) — входит в MVP. **Визуальный граф** отношений — P2 (не MVP).

### S5. Возврат к проекту после перерыва

| | |
|--|--|
| **Триггер** | Автор открывает проект с обзора / dashboard |
| **Шаги** | Видит последнюю сцену, прогресс, 1–3 следующих действия; продолжает письмо одним действием |
| **Результат** | Возобновление работы без поиска «где я был» |
| **Исключения** | Пустой проект — onboarding-подсказки, не «ложный % готовности» без цели по объёму |

**Приоритет:** P0 / Must (Alpha).

### S6. Экспорт рукописи

| | |
|--|--|
| **Триггер** | Автор выбирает экспорт проекта / части / сцен |
| **Шаги** | Выбирает формат и область; получает файл |
| **Результат** | Alpha: DOCX или TXT. Beta: + PDF, Markdown, ZIP проекта |
| **Исключения** | Пустой выбор — валидация. Ошибка генерации — сообщение и повтор без порчи данных |

**Приоритет:** DOCX/TXT P0 Alpha; остальные P1 Beta.

### S7. AI-помощь по контексту (Beta)

| | |
|--|--|
| **Триггер** | Автор запускает AI для сцены / выделения / выбранных сущностей |
| **Шаги** | Видит состав контекста до отправки; получает предложение; принимает / частично / отклоняет (diff) |
| **Результат** | Текст меняется только после явного принятия |
| **Исключения** | Отказ провайдера — понятная ошибка. Контекст Level 4–5 (весь проект) — вне MVP (P2) |

**Приоритет:** P1 / Should (Beta).

## 6. Объём (MoSCoW ↔ P0/P1/P2)

Полная таблица возможностей, спринтов и статусов: **[MVP Scope Matrix](../roadmap/MVP-SCOPE-MATRIX.md)**.

| MoSCoW | Внутренний код | Смысл | Релиз-gate |
|--------|----------------|-------|------------|
| **Must** | P0 | Без этого нельзя проверить ядро / безопасно пилотировать Alpha | Closed Alpha (+ часть P0 до Beta: auth recovery, a11y) |
| **Should** | P1 | Сильно усиливает MVP | MVP Beta |
| **Could** | P2 | Backlog после Beta / Launch | Post-MVP / Launch+ |
| **Won't** | — | Не-цели §3.4 | — |

### 6.1. Must (сводка P0)

- Auth: регистрация / вход / выход (email); к Beta — confirm, reset, профиль, удаление + выгрузка.  
- Проекты: CRUD по названию, dashboard, onboarding-пути, обзор.  
- Рукопись: части / главы / сцены, навигатор, статусы, DnD, soft delete.  
- Редактор: TipTap, автосохранение, offline-буфер, метаданные, контекстная панель, фокус, счётчик слов.  
- Знания (**MVP**): **описание героев**, **описание локаций**, **связи между героями** (список/карточка, не визуальный граф); связь сущностей со сценами; поиск по названиям.  
- Экспорт DOCX/TXT.  
- Empty/loading/error на P0-экранах; desktop-first; WCAG AA на P0 к Beta.

### 6.2. Should (сводка P1 → Beta)

- Сюжетная доска, методы построения сюжета, сюжетные линии, таймлайн-список, заметки/материалы.  
- Полнотекст поиск; экспорт PDF/MD/ZIP; импорт.  
- AI-чат с выбором контекста, accept/diff, настройки приватности.  
- История версий / merge UX; command palette.

### 6.3. Could / позже (P2)

- OAuth, 2FA, workspaces, real-time collab.  
- **Визуальный граф** отношений героев, визуальный таймлайн, профиль стиля, AI Level 4–5, BYOK.  
- WritingGoal / DailyStat (до **DEC-012**).  
- Onboarding v2, биллинг (DEC-004).

### 6.4. Решения по бывшим противоречиям v1.0

| Тема | Решение |
|------|---------|
| Сюжет / AI / templates в «MVP» | P1 → **Beta** (§27 / матрица) |
| Поиск | Названия P0; полнотекст P1 |
| Экспорт | DOCX/TXT P0; PDF/MD/ZIP P1 |
| Auth recovery | Sprint 6, gate **Beta** |
| WritingGoal / DailyStat | **P2** до DEC-012 |

## 7. Функциональные требования

Формат: **ID · приоритет · поведение · критерии приёмки**. Одна формулировка — одно поведение. Детализация задач — в User Stories и Roadmap.

### 7.1. Auth и аккаунт

| ID | P | Требование | Acceptance Criteria |
|----|---|------------|---------------------|
| FR-AUTH-01 | P0 | Пользователь регистрируется по email и паролю | Аккаунт создаётся; после регистрации доступен вход в приложение; ошибки валидации понятны |
| FR-AUTH-02 | P0 | Пользователь входит и выходит | Сессия устанавливается/завершается; защищённые маршруты недоступны без сессии |

## 9. Данные, аналитика и интеграции

### 9.1. Продуктовые сущности (уровень PRD)

Проект → ManuscriptNode (часть / глава / сцена) → содержимое сцены; Character (описание героя); CharacterRelationship (связи между героями, MVP); WorldArticle (в т.ч. локации с описанием); (P1) Storyline / Beat / TimelineEvent / Note; (P1) AIConversation; Version.

Инварианты (продуктовые):

- Сцена = узел типа `scene`; текст хранится отдельно от дерева.  
- Soft delete; счётчик слов — кэш от plain text.  
- Статусы сцены не блокируют редактирование.

Схема реализации: [DATABASE.md](../technical/DATABASE.md) — **не дублируется** в PRD.

### 9.2. Аналитика

**North Star (Гипотеза v1.0):** число активных проектов, где пользователь создаёт/редактирует содержательный текст минимум в две разные недели месяца.

**Активация (определение):**

1. Создан проект.  
2. ≥3 структурных элемента.  
3. ≥300 слов.  
4. Возврат в течение 7 дней.

**События (без текста рукописи):**  
`scene_opened`, `scene_created`, `scene_text_changed`, `scene_autosave_succeeded`, `scene_autosave_failed`, `focus_mode_enabled`, `context_panel_opened`, `ai_action_started`, `ai_suggestion_accepted`, `version_restored`.

## 12. Критерии приёмки релизов

### 12.1. Closed Alpha

Автор проходит: **регистрация → проект → структура → сцена → описание героя и локации → связь между героями → экспорт DOCX/TXT** без потери текста при кратком offline.

**Не требуется на Alpha:** AI, plot board, templates, timeline, import, full-text search, billing.

### 12.2. MVP Beta (= «MVP» продукта)

- Все **P0 + P1** по Scope Matrix.  
- ≥70% тестовых авторов завершают путь до первой сохранённой сцены.  
- Нет потери подтверждённого текста в типовом offline.  
- Usability ≥5 авторов.  
- WCAG AA на P0-экранах.  
- Privacy policy + AI consent.  
- Мониторинг ошибок, бэкапы.  
- Критичные DEC для Beta — Accepted или явно сняты.

### 12.3. Public Launch

Тарифы (DEC-004), OAuth по плану, onboarding v2, справка, расширенная аналитика, legal (DEC-007).
