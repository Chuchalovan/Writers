## 1. Краткое резюме

Авторы художественной прозы держат текст, структуру, персонажей и заметки в разных инструментах. Связи теряются, план расходится с рукописью, универсальный AI не знает контекст проекта — проекты чаще бросаются до черновика.

**Предложение:** «Манускрипт» — единая спокойная среда, где проект книги, структура частей/глав/сцен, база знаний и редактор связаны; AI помогает только по выбранному контексту и не меняет текст без явного действия. Автор может **создать произведение по одному из методов построения сюжета** (трёхактная структура, путь героя, beat sheet и др.) либо начать без метода.

**Ожидаемый эффект:** быстрее путь от идеи к первому черновику; выше возврат к письму; готовность к монетизации на Public Launch. Целевые ROI/MRR — **TBD** после [DEC-004](../roadmap/DECISION-LOG.md#dec-004-тарифы-free--paid).

**Крайний срок бизнес-горизонта MVP Beta:** Phase 2 по [Roadmap](../roadmap/ROADMAP.md) (после закрытия P0 + P1).

## 3. История проекта и необходимость

### 3.1. Проблема

Когда автор пишет художественную прозу, материалы разнесены по редактору, таблицам, заметкам и чатам. Следствия:

- трудно перейти от идеи к плану;  
- план и рукопись расходятся;  
- поиск факта прерывает поток;  
- AI без контекста проекта навязывает чужой голос;  
- профессиональные комбайны перегружают новичка.

### 3.2. Необходимость сейчас

**Факт:** продукт уже в разработке (Phase 0 ✅, Sprint 1–2 частично). Без зафиксированного BRD бизнес-границы и обязательность **методов построения сюжета** остаются только в разрозненных PRD/матрице.

**Гипотеза ценности:** единая среда + выбор метода сюжета (или осознанный отказ от метода) + контекстный AI → быстрее черновик и меньше брошенных проектов.

### 3.3. Аудитория (бизнес-сегменты)

| Сегмент | Ценность для бизнеса |
|---------|----------------------|
| Начинающий автор | Активация через шаблоны/методы и next step |
| Автор-планировщик | Удержание за счёт структуры, доски, методов |
| Автор-импровизатор | Низкий порог входа (старт без метода / со сцены) |

## 4. Объём проекта

### 4.1. Входит в объём (In scope)

- Web-приложение desktop-first (ru/en).  
- Аккаунт, проекты, рукопись (части/главы/сцены), редактор с автосохранением.  
- База знаний (**MVP / Must**): **описание героев**, **описание локаций**, **связи между героями**; связь со сценами; сюжетная доска (Should/P1).  
- **Создание и ведение произведения с выбором одного метода построения сюжета** из [каталога](./plot-methods.md) (Must-набор к Beta).  
- Экспорт; к Beta — AI по выбранному контексту, поиск, импорт (per Scope Matrix).  
- Закрытая Alpha → MVP Beta → подготовка Public Launch.

### 4.2. Не входит (Out of scope)

Соцсеть, маркетплейс редакторов, типографская вёрстка, автопубликация, real-time co-authoring, генерация целой книги одной командой, полноценное mobile-приложение, все Could-методы сюжета в MVP.

### 4.3. Этапы и deliverables (бизнес-уровень)

| Этап | Deliverable | Критерий приёмки (бизнес) |
|------|-------------|---------------------------|
| Phase 0 | Документация, monorepo, CI, схема | Инфра готова к разработке |
| Phase 1 Alpha | Ядро письма + структура + **описание героев и локаций** + **связи между героями** + экспорт DOCX/TXT; старт **без** обязательного метода | Сценарий Alpha из PRD §12.1; BR-FR-05…05c |
| Phase 2 Beta | P0+P1; **Must-методы сюжета** доступны при создании/планировании | PRD §12.2 + BRD BG-2/BG-3 |
| Phase 3 Launch | Тарифы, OAuth по плану, справка, legal | DEC-004, DEC-007 |
| Phase 4 | P2 / Could-методы | Backlog |

Детальный sprint SoT: [MVP Scope Matrix](../roadmap/MVP-SCOPE-MATRIX.md).

## 7. Сценарии использования (бизнес)

Краткие бизнес-формулировки. Потоки, исключения и постусловия — в [каталоге use case](../user-stories/use-cases.md).

### UC-1. Быстрый старт без метода

Автор регистрируется, создаёт проект только по названию, сразу пишет сцену.  
**Цель:** activation импровизатора.  
**Связь:** Must `blank`.

### UC-2. Создание произведения по методу сюжета

Автор при создании или в разделе «Сюжет» выбирает **один** метод (например, трёхакт или путь героя). Система создаёт каркас (акты/биты/точки) с пояснениями простым языком. Автор заполняет каркас и пишет сцены, связанные с элементами плана. Метод можно сменить или ослабить позже без потери текста рукописи.  
**Цель:** BG-3, удержание планировщиков и новичков.  
**Связь:** Must-методы из каталога.

### UC-3. Письмо с контекстом

Автор пишет сцену; рядом герои/локация/цель; автосохранение и буфер при потере сети.  
**Цель:** черновик без потери текста.

### UC-3a. Описание героев и локаций

Автор создаёт карточки героев и локаций с текстовым описанием (имя/название обязательно; остальные поля опциональны), привязывает их к сценам.  
**Цель:** единая база фактов мира в MVP.  
**Связь:** BR-FR-05, BR-FR-05a.

### UC-3b. Связи между героями

Автор на карточке героя задаёт связи с другими героями (тип + опциональный комментарий), просматривает и редактирует их. Визуальный граф не обязателен для MVP.  
**Цель:** удерживать отношения персонажей без внешних таблиц.  
**Связь:** BR-FR-05b.

### UC-4. Возврат после перерыва

Обзор проекта: continue + 1–3 next step (в т.ч. «заполнить следующий бит метода»).  
**Цель:** D7 retention.

### UC-5. Экспорт

Автор выгружает рукопись (DOCX/TXT на Alpha; расширенно на Beta).  
**Цель:** доверие, «данные принадлежат автору».

### UC-6. AI по контексту (Beta)

Автор запускает помощь с явным составом контекста; принимает/отклоняет diff.  
**Цель:** ускорение правок без потери голоса.

## 8. Требования к продукту

### 8.1. Функциональные требования — ДОЛЖНЫ БЫТЬ (Must)

Определяют успех Alpha/Beta на бизнес-уровне. Детализация AC — в PRD / User Stories.

| ID | Требование |
|----|------------|
| BR-FR-01 | Пользователь регистрируется, входит и работает со своими проектами (email/password; recovery к Beta). |
| BR-FR-02 | Пользователь создаёт проект по названию и управляет списком проектов. |
| BR-FR-03 | Пользователь строит рукопись: части → главы → сцены, со статусами и порядком. |
| BR-FR-04 | Пользователь пишет сцену в редакторе с автосохранением и без потери текста при кратком offline. |
| BR-FR-05 | **Описание героев (MVP):** пользователь создаёт и редактирует карточки героев (имя обязательно; роль, описание, внешность, мотивация, заметки — опционально) и связывает героев со сценами. |
| BR-FR-05a | **Описание локаций (MVP):** пользователь создаёт и редактирует локации с названием и текстовым описанием (и опциональными заметками/тегами), связывает локации со сценами. |
| BR-FR-05b | **Связи между героями (MVP):** пользователь выстраивает связи «герой — тип связи — герой» с опциональным комментарием; просматривает и изменяет связи на карточке героя. Визуальный граф отношений — не Must (Could / post-MVP). |
| BR-FR-05c | Пользователь ведёт прочие базовые статьи мира (не только локации), связанные со сценами. |
| BR-FR-06 | Пользователь экспортирует рукопись в DOCX и TXT (Alpha); расширенные форматы — по Scope Matrix (Beta). |
| BR-FR-07 | **Пользователь может создать и вести произведение, выбрав один метод построения сюжета** из поддерживаемого Must-каталога, **либо** начать без метода (`blank`). |
| BR-FR-08 | При выборе метода система предоставляет **каркас планирования** (акты / шаги / биты) с подсказками простым языком и возможностью связать элементы каркаса со сценами рукописи. |
| BR-FR-09 | Выбор метода **не блокирует** свободное редактирование текста; смену метода или возврат к `blank` можно выполнить без удаления текста сцен. |
| BR-FR-10 | Must-методы к MVP Beta: `blank`, `three-act`, `heros-journey`, `beat-sheet` — см. [plot-methods.md](./plot-methods.md). |
| BR-FR-11 | P0-экраны имеют состояния empty / loading / error; UI ru/en. |

### 8.2. Функциональные требования — СЛЕДУЕТ ИМЕТЬ (Should)

Добавляют ценность к MVP Beta / сразу после.

| ID | Требование |
|----|------------|
| BR-FR-20 | Сюжетная доска (карточки, DnD) и сюжетные линии. |
| BR-FR-21 | Методы **Should:** `snowflake-lite`, `string`, `index-cards` (карточки ≈ доска). |
| BR-FR-22 | Таймлайн-список событий; заметки/материалы. |
| BR-FR-23 | Полнотекстовый поиск; импорт; экспорт PDF/Markdown/ZIP. |
| BR-FR-24 | Контекстный AI с прозрачным контекстом и accept/diff. |
| BR-FR-25 | История версий сцен; обзор проекта с next step, учитывающим прогресс по методу. |
| BR-FR-26 | Подсказки «как выбрать метод» (новичок / белый лист / дедлайн) из каталога. |

### 8.3. Функциональные требования — ЖЕЛАТЕЛЬНО ИМЕТЬ (Could)
