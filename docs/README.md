# Документация «Манускрипт»

Единая структура продуктовой и технической документации.

## Карта документов

| Раздел | Назначение | Аудитория |
|--------|------------|-----------|
| [PRD](./prd/) | Что строим: продукт, scope, UX, критерии успеха | Product, Design, Eng |
| [BRD](./brd/) | Зачем строим: бизнес-цели, рынок, метрики, риски | Business, Product |
| [ТЗ](./tz/) | Как реализуем: требования к системе, интеграции, НФТ | Eng, QA |
| [Roadmap](./roadmap/) | Когда: фазы, спринты, приоритеты, решения | Product, Eng |
| [User Stories](./user-stories/) | Для кого и в каком сценарии: эпики и истории | Product, Design, Eng, QA |
| [Technical](./technical/) | Справочники: архитектура, API, БД, дизайн-handoff | Eng, Design |

## Порядок чтения

```
BRD  →  PRD  →  User Stories  →  ТЗ  →  Roadmap  →  Technical
```

1. **BRD** — бизнес-контекст и цели  
2. **PRD** — продуктовая спецификация и scope  
3. **User Stories** — сценарии пользователя (декомпозиция PRD)  
4. **ТЗ** — техническая постановка для разработки  
5. **Roadmap** — план поставки и статусы  
6. **Technical** — детальные инженерные справочники

## Правила ведения

- Один основной документ на раздел; детали — в подпапках или связанных файлах  
- **PRD** отвечает на «что и зачем»; **ТЗ / technical** — на «как»  
- При расхождении по scope побеждает [MVP Scope Matrix](./roadmap/MVP-SCOPE-MATRIX.md)  
- Версии и статусы указываются в шапке каждого документа  
- Перекрёстные ссылки обязательны (не дублировать длинные разделы)  
- В PRD помечайте **Факт / Гипотеза / Решение**
